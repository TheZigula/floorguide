## Base-url defect fixed, and a commit message I corrupted — 14:05
1. THE DEFECT: the public page read "Backend unreachable" with 404s while the cloud `/health` was healthy on b22c130. Cause: piping the value into `vercel env add` from PowerShell 5.1 stored it as `﻿https://...` — a UTF-8 BOM in front of the URL. My earlier verification missed it because I used a substring `-like` match, which passes with a BOM present. Printing the characters escaped is the only honest check.
2. WHY THE SOURCE HARDENING DID NOT SAVE IT: `frontend/src/api/client.ts` already did `(...).trim().replace(/\/+$/,"")` and JS `trim()` does strip U+FEFF at runtime — but the built bundle read `` ue=`<BOM>https://...`.replace(...) `` with NO `.trim()` left. The minifier constant-folded the trim at build time and that fold did not treat U+FEFF as whitespace. So `client.ts` needed no change; it was already correct.
3. FIXED AND PROVEN THROUGH THE PAGE, NOT THE BUNDLE: removed the variable, re-added it from a byte-exact file (`UTF8Encoding($false)`, no trailing newline, 43 bytes, first bytes `0x68 0x74 0x74`) via `cmd /c "vercel env add ... < file"`, redeployed. No browser extension was available, so the one /chat *driven through the page UI* is still unproven; the same request path was proven at HTTP level with the Vercel `Origin` and a matching `Access-Control-Allow-Origin`.
